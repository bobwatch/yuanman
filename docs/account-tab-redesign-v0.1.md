# 沅满记账 · 「账户」Tab 页重构 —— 总体设计方案 v0.2

> 定位：移动端记账 App「沅满」底部第 3 个 Tab（`Screen.Account`）。本文是**视觉与交互**的总体设计方案，
> 面向后续一次性落地实现。设计语言遵循 App 既有质感主张：**轻快、干净、克制**，浅色/深色双主题自适配。
>
> 代码基线：`feature/account-v0.0.4`（当前工作区存在一版未提交的「信息过载」实现，本文即针对其重构）。
> 文中所引代码位置均基于该基线。
>
> **v0.2 修订（产品约束）**：① 对账是必需的一等功能，页面须有显性的对账入口与提醒，不允许只埋在账户操作面板深处；
> ② 账户类型与账户内容**完全由用户自定义**——类型只是用户起的名字，代码不得内置任何类型的语义（无"信用组置底"、
> 无按类型的颜色/排序特判）；正负余额的赤红/还款语义只由余额符号决定。

---

## 0. 一句话设计主张

**页面只回答一个问题：「我现在到底有多少钱，钱都在哪儿」—— 让金额做主视觉，让账户清单做正文，让高频操作退到一层之内可达。**

重构的本质不是加功能，而是**做减法**：减少视觉图层、减少每行的信息条数、减少并列的强调手段，让「净资产大数字 → 账户清单」成为一眼可读的两层结构。

两条产品红线贯穿全案：

1. **对账是一等公民**。页面常驻一个"待核对"提醒入口（见 §4.5），每月例行对账最多 3 次点击完成；
2. **类型零语义**。账户类型=用户自由命名的字符串（可不设），全代码不得读类型名做分支/排序/配色特判。页面只有两类"语义色"来源：余额符号（负=赤红）与对账时效（待核对=琥珀）。

## 1. 现状诊断（基于当前实现逐条取证）

### 1.1 视觉噪音：装饰与信息双重复
| 问题 | 取证 | 后果 |
|---|---|---|
| 头部卡复刻首页 `FinancialOverviewCard` 的斜纹 + 双光晕 `drawBehind`（`AccountComponents.kt:82-117`），且首页卡本身已带同类纹理 | `AccountOverviewHeroCard` 全量重绘 | 两个 Tab 顶部质感雷同；纹理层级低对比度，但叠加后"浮层多" |
| 头部卡内堆叠 4 套并列信息体系：资产/负债对称面板、分布彩条 + **独立图例行**、3 枚月度指标胶囊 | `AccountComponents.kt:229-410` | 一块卡里有 6 种视觉强调手段（色点、分割线、彩条、图标行、胶囊），无主次 |
| 每张账户卡 4 行文本：名称、label 徽章、本月入/出、对账时效 + 余额 + 还款钮 + more 钮 | `AccountComponents.kt:691-846` | 单行卡片高度膨胀、扫描成本高 |

### 1.2 交互问题
- **全局动作栏喧宾夺主**：转账/新建/对账三个并排按钮（`AccountComponents.kt:477-602`）中，「资金对账」默认对第一个账户直接弹对账框（`AccountScreen.kt:118-125`），动作语义含混——用户不知道"对谁对账"。
- **行内"还款"微按钮**语义依赖外部状态：点击时偷偷挑选"第一个正余额账户"当付款方（`AccountScreen.kt:180`），转出方由系统代替用户决定，缺少确认感。
- 入口分层与 App 惯例不一致：全 App 对「一条记录的详情/操作」统一用"点击 → 操作底包"（明细页 `RecordDetailCard` 模式），账户页却把操作藏在行尾 "…" 小图标里，点击命中率差、可发现性弱。
- 下拉刷新是 350ms 假刷新（`AccountViewModel.kt:185-191`），结束后弹"刷新成功" toast，自欺且吵闹。

### 1.3 违背"类型全自定义"的既有实现（重构必须一并修正）
- **预设类型写死**：新建账户弹层只有 5 个固定 FilterChip（`AccountComponents.kt:993`：流动活期/储备资金/信用借贷/现钞零钱/投资理财），无法输入自定义类型。
- **分组排序按账户数**：`AccountViewModel.kt:133` `sortedByDescending { size }`，且默认种子、示例代码里反复把"信用借贷"当特例（注释/排序假设）——类型必须回归纯数据。

### 1.4 结论：保留什么、砍什么
**保留**（功能与产品意图正确）：净资产主指标、资产/负债二分、账户类型分组（改为纯用户标签）、负余额赤红、隐私切换（已全局持久化于 `PreferencesRepository.privacyMode`）、转账/还款、资金对账（含期初基线校正模型，见 AccountEntity 注释语义）、删除二次确认。
**重构**（本文重点）：一切"多余的框、线、图例行、胶囊按钮"；信息密度；分组的顺序/口径；操作入口层级；**类型输入方式**。

## 2. 设计目标与原则

1. **金额主角**：一个数字区（净资产）一个数字（余额）。同一屏内，**只允许一种"大号数字 + 强调色"**，其余一律降为说明文字。
2. **页面只两层 + 一条提醒**：上 = 资产快照（hero），下 = 账户清单；清单上方可有一条**对账提醒横幅**（有逾期才出现）。其余所有操作（转账/对账/编辑/删除）是账户的"动作"，收进**账户操作面板**（一层可达）。
3. **一个状态一件事**：负余额/待对账等"异常"用文字 + 单色点表达，不引入第二套彩条、不引入图标行。
4. **与全 App 同构**：复用明细页已确立的交互范式（点行 → 操作底包、破坏操作 Dialog 二次确认、删除后 Toast）、复用主题 token 与圆角档位，不创造第四套筛选/按钮/卡片语言。
5. **双主题原生**：只用 `colorScheme` 语义角色 + 记账语义色（`ExpenseColorLight/Dark`、`IncomeColorLight/Dark`），不硬编码新的强调色。
6. **克制不等于无聊**：允许 1 处低对比装饰（分布彩条），它是唯一允许出现的"色带"。

## 3. 页面信息架构

### 3.0 领域模型澄清（本次修订的产品前提）
- **账户**：名称、类型、图标、主题色、期初余额 —— 全部由用户设置。余额语义仅由符号决定（`balanceCents < 0` → 赤红/可"还款"）。
- **账户类型**：零语义的字符串分组标签。可为空（归入「未分组」）。没有内置类型、没有类型配色、没有"类型应置底/置顶"规则。
- **对账**：每个账户一个"上次核对时间"（`lastReconciledAt`）+ 差额记录；页面据此产生提醒与状态。

### 3.1 信息清单（全部来源于 `AccountUiState` / `AccountUiModel`）
| 层级 | 信息 | 来源字段 | 隐私模式表现 |
|---|---|---|---|
| H1 | 净资产（可负） | `totalBalanceCents` | `¥ ••••` |
| H1 副 | 总资产 | `totalAssetCents` | 隐藏 |
| H1 副 | 待还负债（仅 ≠0 时出现，赤红） | `totalDebtCents`（负数） | 隐藏 |
| 装饰 | 资金分布彩条（有正资产且账户 ≥2 时） | `accounts`（正余额、按列表序） | 保留彩条（不含数字） |
| 提醒 | 待对账横幅（存在逾期账户时） | 各 `lastReconciledAt` | — |
| 组头 | 类型名 · 账户数 | `groups[].label/count` | — |
| 组头右 | 组合计（组净值，可负） | `groups[].groupTotalCents` | 隐藏 |
| 账户行 | 名称 / 类型 | `name/label` | — |
| 账户行 | 余额（可负，负则赤红） | `balanceCents` | `¥ ••••` |
| 账户行副行 | 类型 · 账务状态（对账时效） | `label`、`lastReconciledAt` | — |
| 空态 | 无账户引导 | — | — |

**明确不展示**（从主页面拿掉，降噪）：单账户"本月入/出"、单账户对账时效的常驻文字、跨组分布图例行、月度出入三枚指标胶囊。它们各有去处：本月入/出与对账详情 → 账户操作面板；对账提醒 → §4.5 横幅；月度收支汇总 → 首页卡已承担。

## 4. 逐区块规格

### 4.1 区块 A：净资产快照卡（`AccountSnapshotHero`）

替换现 `AccountOverviewHeroCard`。差异：**删除斜纹/双光晕 drawBehind、删除资产/负债对称面板框、删除分布图例行、删除三枚月度胶囊**。

| 元素 | 规格 |
|---|---|
| 容器 | 与首页顶卡同构：无水平边距贴边，`topStart/topEnd=0`、`bottom=22dp`；`elevation=0`，container 透明用 `drawBehind` 填 `surface`；外描边 `1dp outlineVariant a0.35`；内容 `.statusBarsPadding()` 后 `padding(h=20,v=14)` |
| 行1 标题 | 7dp 主色圆点 + 「净资产」13sp SemiBold `onSurfaceVariant` |
| 行1 右侧 | 隐私钮：32dp 圆形 `surfaceVariant a0.65`，图标 16dp `Visibility/VisibilityOff`（沿用现有样式与位置） |
| 行2 主数字 | `¥` 前缀 22sp Bold + 整数 `36sp Bold letterSpacing -0.4sp`（`displayLarge` 覆写），整数/小数分色：整数 `onSurface`、小数 `.78 比例` `onSurfaceVariant`；**负值整体 `ExpenseColorLight/Dark`** 且前置 `-¥` |
| 行3 说明 | 12sp；`总资产`(label `outline`) 值(Bold `onSurface`)；若 `totalDebtCents != 0` 追加分隔「·」与 `待还负债`+赤红绝对值（正文始终显示正数便于阅读，赤红传达语义）。负债判定只依赖符号，与任何类型名无关 |
| 行4 彩条 | 4dp 高、rounded 3、`surfaceVariant` 轨道；分段色 = 各**正余额账户的 `colorHex`**，按列表序排列（与下方清单颜色天然呼应，图例即清单）；仅当 `totalAsset>0` 且正余额账户 ≥2 时显示；**不渲染任何百分比文字** |
| 隐私态 | 主数字→`¥ •••••`（点数≈真实位数防跳版）；行3 两值→`••••`；彩条保留 |

**数字字体细节**：小数始终两位；三位分组；负数符号紧跟 `¥` 前。金额 >= `1 亿` 时仍全量显示（克制期不引入 `万/亿` 缩写，避免口径分叉）。

### 4.2 区块 B：账户清单

#### 4.2.0 类型自定义（全局规则）
- 类型名即 `label` 字段，**自由文本**，可空（空 → 归入「未分组」，存储仍为空串）。
- 全 App 无任何代码读 `label` 内容做分支；页面不按类型强制配色、不强制排序位。
- 新建/编辑账户弹层的类型选择改为：**自由文本输入框 + 下方"已用类型"快捷横滑 chips**（自动收集当前所有账户的既有类型去重展示，随输入过滤）。没有写死的预设类型；首启为空态/示例时，可用种子账户自带的类型作为自然示例（也仅示例，可随意删改）。
- 当某类型的最后一个账户被删除/改类型后，该类型自动消失（类型无独立存储，随账户聚出）——见 §8.3。

#### 4.2.1 分组顺序（纯数据规则，无内置语义）
- 组内：按 `sortOrder` 升序（现有字段）。
- 组间：按「各组账户最小 `sortOrder`」升序 —— 即**类型顺序由最早建立的账户决定**，新增账户追加进所属组尾，页面顺序天然稳定、可预期。
- 「未分组」恒居最末（这是唯一的特判，且它**不是一种类型**，只是无类型账户的兜底容器）。
- 拖动整组排序/在"账户类型管理"里调整类型顺序 → 列入 Phase C（复用项目已有的拖拽排序能力）。

#### 4.2.2 组头（`AccountGroupHeader` 重制）
- 左：**4dp×12dp 圆角竖条**，颜色 = 组内**首个**账户 `colorHex`（无类型特判；空竖条色回退 `outline`）。
- 组名 14sp SemiBold `onSurface` + 「· N」12sp `onSurfaceVariant`；组名为空显示「未分组」（12sp，`outline`，弱化呈现）。
- 右：`合计` 12sp —— 组净值 `groupTotalCents`；`<0` 赤红并带 `-¥`，`≥0` 正常色。
- 上下留白 `pad(top=16,bottom=6)`。整组点击折叠/展开列为 Phase C 增强。

#### 4.2.3 账户行（`AccountItemCard` 重制，重点瘦身）
单行卡片 r16、`surface` 底、`elevation 0.5`、`1dp outlineVariant a0.35` 描边；内衬 `14/10`；横向 16dp 外边距、行距 8dp。

```
┌────────────────────────────────────────────┐
│  (◎) 招商银行储蓄卡            ¥52,000.00    │
│       储蓄 · 本月已核对                     │
└────────────────────────────────────────────┘
┌────────────────────────────────────────────┐
│  (◎) 花呗 / 信用卡             -¥1,580.00    │   ← 赤红（符号决定）
│       信用/花呗 · 12 天未对账       [还款]   │   ← 琥珀副行 + 还款钮(仅在负余额)
└────────────────────────────────────────────┘
┌────────────────────────────────────────────┐
│  (◎) 现金零钱                    ¥650.00     │   ← 无类型账户示例
│       · 未对账                              │   ← 类型位留空，仅状态
└────────────────────────────────────────────┘

- 左：`CategoryIconView` 40dp（icon 20dp），语义 = 账户类别图标（用户自选 icon 词表）。
- 主行右：余额 `16sp Bold`；负值 `ExpenseColorLight/Dark`；隐私态 `¥ ••••`。
- 副行（`Modifier.weight(1f)` 撑满，防还款钮位移）：**类型 · 账务状态** 11sp `outline`；无类型时只显示状态（前面留空）。状态文案与配色表见 §7。
- **删除**：行内「本月入/出」文字、label 独立徽章、"…" more 钮。→ 收入操作面板。
- 整个行可点 → 打开账户操作面板（§4.3）。行内不给第二可点元素（除负余额的还款钮）。

> 设计依据：账户行与明细行必须有**可区分的身份**——明细行双行紧凑 r12、右侧金额带 `+/−` 符号；账户行 r16、余额不带符号、负余额直接赤红、卡片高度统一——两 Tab 同滚过时不会混淆。

#### 4.2.4 新建账户入口
列表末尾「新建账户」**幽灵卡**：与账户行同尺寸圆角，`surfaceVariant a0.4` 底 + **虚线描边**（`drawBehind` 画 DashPath，`outline a0.6`），居中 13.5sp Medium `onSurfaceVariant`，⊕ 图标 18dp。点击 → `AddEditAccountSheet(accountToEdit = null)`（类型选择按 §4.2.0 重做）。
**空态**：无账户时整页进入 `EmptyStateView`（icon `AccountBalanceWallet`、标题「创建第一个账户」、主按钮「新建账户」），hero 与横幅随空态隐藏。

### 4.3 区块 C：账户操作面板（`AccountActionSheet`，核心交互改造）

**入口变化**：账户行点击 → 操作面板；长按与 "…" 全部取消，统一为行点击。交互范式对齐明细页"点行 → 操作底包"。

│        ↑ 本月入 ¥1,500 · ↓ 本月出 ¥240     │ ← 状态行：icon 11dp 收/支色 + 文本 11.5sp outline
│        ✓ 本月已核对（上次 8 月）            │ ← 账务状态：✓主色 / ⚠琥珀(逾期) / ○灰(从未)
├──────────────────────────────────────────┤
│  转账 / 还款      （secondary）            │ ← 主操作：16dp 图标 + 13.5sp，List 高 56dp
│  资金对账         （primary）              │
│  编辑账户         （onSurface）            │
├──────────────────────────────────────────┤
│  删除账户         （error 红字）            │ ← 触发行底部，语义分区上移分隔
│  删除前仍走 ConfirmDeleteDialog 二次确认     │
└──────────────────────────────────────────┘
```

- **转账 / 还款** → `QuickTransferSheet`，本账户预填为"转出"（`initialFromAccountId = account.id`）；若本账户为负余额，弹层标题自动切「还款」，语义 = 从正余额账户转资金回补该负余额（通用，不依赖类型名）。
- **资金对账** → 现 `AccountReconcileDialog`（原样复用，含差额提示与期初基线校正）。
- **编辑账户** → `AddEditAccountSheet(accountToEdit = account)`（含类型自由输入 §4.2.0）。
- **删除账户** → `ConfirmDeleteDialog` 后 `viewModel.deleteAccount`。
- 状态行取 `AccountUiModel.inCents/outCents/lastReconciledAt`，本月入/出**仅在此处展示**——既保留信息又不污染列表。

### 4.4 区块 D：下拉刷新（重制）

保留 `YuanmanPullRefreshIndicator` 交互与胶囊外观（与明细页一致）。行为修订：
- 移除"刷新成功"toast（`AccountScreen.kt:73-78` 现有逻辑）；
- 刷新语义改为「重新统计」（`viewModel.refresh()` 保留 350ms 占位即可），指示器只表达进行中状态；
- 空态下页面仍可下拉（保留现有 verticalScroll 包裹空态的做法）。

### 4.5 区块 E：对账提醒横幅（一等公民入口，v0.2 新增）

清单顶部、hero 之下的一条**状态横幅**，满足条件才出现（任一账户"逾期未对账"，定义见 §7）：

```
┌──────────────────────────────────────────────┐
│ ⏱  2 个账户待核对           [去对账 →]        │
│    上次核对均早于本月 · 建议按网银/账单月核一次 │  ← 12sp 副文案（可省略，见下）
└──────────────────────────────────────────────┘
```

- 外观：`surfaceVariant a0.5` 底、r14、琥珀色 16dp 图标 + 琥珀强调词；非警示红绿。
- **行为**：点击横幅 → 弹出「待核对账户」底包：逾期账户逐行列出（图标 + 名 + `上次核对 YYYY年M月` / `从未对账`），每行尾部一个「去对账」按钮，点击即对该账户开 `AccountReconcileDialog`。
- 全部账户都核对过 → 横幅消失（页面对账状态"自愈"）。
- 对账入口由此共两级：横幅（发现逾期、批量入口）+ 账户行点击 → 面板「资金对账」（随时单账户对账）。**删除旧的全局"资金对账"动作栏**。

## 6. 交互规格

### 6.1 状态与反馈总表
| 交互 | 触发 | 视觉/行为反馈 | 动效规范 |
|---|---|---|---|
| 隐私切换 | hero 眼睛钮 | 金额在明文/`••••` 间**原位交叉淡化**；眼睛图标淡切 | `Crossfade`/`AnimatedContent` 160ms + `scale .98→1`；haptic `TextHandleMove`；状态持久化（现 VM 已具备） |
| 打开操作面板 | 点击账户行 | 行 `ripple`；底包 `skipPartiallyExpanded` 升起 | 系统 ModalBottomSheet 默认；haptic |
| 打开转账 | 面板「转账/还款」或负余额行[还款]钮 | 面板回落 → 转账底包升起（预填本方） | 先关后开，间隔 ~100ms 避免同帧双弹 |
| 打开对账横幅 | 点击横幅 | 升起「待核对账户」底包 | 默认底包动效 |
| 单账户对账 | 面板「资金对账」/ 底包行内「去对账」 | 差异行实时红/绿换算（现有 Dialog 已实现，样式沿用）；成功 → 横幅同步消失 | — |
| 新建账户 | 幽灵卡 / 空态按钮 | 底包；保存成功 → 新账户**插入其类型组**并 `animateItem` 归位 | `LazyColumn.animateItem` 200ms |
| 删除 | 面板「删除」 | Dialog 二次确认 → 行 `fade+scaleOut` 收起 → Toast（可撤销，若做撤销则复用明细页 undo 模式） | 收起 180ms FastOutSlowIn |
| 下拉刷新 | 顶部下拉 | 现胶囊指示器，**无 toast** | 复用组件 |
| 负余额还款钮 | 点击 | 直开转账底包，from=首个正余额≠本卡，to=本卡 | — |

> 点击防抖沿用全 App `clickableDebounce(500)` 惯例。

### 6.2 隐私模式全局一致性
隐私状态来自 `preferencesRepository.privacyMode`（全局唯一开关）。账户页全部金额出口（hero、组合计、行余额、面板头部余额、待核对底包中的余额位）走同一 `maskAmount()` 工具（`¥ •••••`）。

### 6.3 手势
- 行内无横向滑动（账户行不做 swipe-delete：删除是低频且危险操作，收敛到面板 + Dialog，比明细页"滑出仍须点确认"更保守）。
- hero 固定不随列表上卷（与现结构一致）。

## 7. 文案与状态规格

### 7.1 对账状态定义（横幅与副行的共同口径）
| 状态 | 判定（按月，对齐现 `calculateReconcileTag` 语义） | 副行/底包文案 | 配色 |
|---|---|---|---|
| 已核对 | 最近核对月 == 当月 | `本月已核对` | `outline` + ✓ 主色 |
| 待核对（上月在档） | 最近核对月 == 上月 | `上月已核对` | `outline` |
| 逾期 | 最近核对月早于上月，或从未核对 | `M 天未对账` / `从未对账` | 琥珀 |
| 从未 | `lastReconciledAt == null` | `从未对账` | `outline`/琥珀（横幅语境琥珀） |

横幅出现条件：存在 ≥1 个「逾期」账户；横幅文案 = `N 个账户待核对` + 副文案 `上次核对早于本月 · 建议按月核对一次`（副文案过长时省略，只留主句）。

### 7.2 页面文案清单
| 场景 | 文案 | 配色 |
|---|---|---|
| 负债为 0 | hero 说明行只显示 `总资产 ¥x` | — |
| 无类型账户行副行 | 只显示状态，类型位留空（如 `· 本月已核对`） | `outline` |
| 空态 | `创建第一个账户` / `微信、支付宝、储蓄卡……先建一个，开始精细资金管理` / 按钮 `新建账户` | EmptyStateView 默认 |
| 幽灵卡 | `新建账户` | — |
| 转账弹层标题 | 目标负余额 = `还款：转入「X」`；否则 `资金转账` | — |
| 类型输入占位 | `输入或选择账户类型，如：日常、储蓄、信用（可留空）` | — |

措辞纪律：全页禁止 emoji 与感叹号堆砌；状态句省略号统一用 `·`（⏱ 为横幅图标，非装饰性 emoji）。

## 8. 数据与口径（UI 依赖的 VM 改造清单）

1. **类型纯数据化**：删除一切读 `label` 做分支的逻辑与种子/示例注释；`label` 仅作字符串透传。
2. **分组排序**（§4.2.1）：`AccountViewModel.kt:133` 的 `sortedByDescending { size }` 替换为「组间按最小 `sortOrder`、组内按 `sortOrder`、未分组垫底」。
3. **已用类型收集**：`AddEditAccountSheet` 的快捷 chips 数据源 = `uiState.accounts.map{label}.distinct()`（VM 提供或 UI 从 state 取）。
4. **分布彩条数据源**：改为 `accounts.filter{balance>0}` 按列表序生成 `DistributionSegment(account.colorHex)`，删除按 label 聚合逻辑。
5. **对账口径风险标注**（不在本迭代强行修）：现"期初 + 仅当月流水"会在跨月漂移。建议 UI 先如实呈现当前口径；数据层改造（期初 + 建账以来全量流水累计 / 启用 Room `accounts` 账本）单独立项，避免 UI 重写期间双线改动。对账的 `lastReconciledAt` 时间戳语义不受影响。
6. `AccountUiModel` 无需增删字段；`isLoading` 目前恒 false，可顺手移除以缩状态面（低优先）。

## 11. 决策记录与开放项

| # | 决策/开放项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 分布彩条按账户色 vs 按组色 | 账户色、按列表序 | 与清单颜色对位，省去图例行；无类型语义 |

| 5 | 琥珀警示色是否抽主题 token | 开放（建议并入） | 与首页预算条同值；抽离需动 `HomeScreen.kt`，另立 commit |
